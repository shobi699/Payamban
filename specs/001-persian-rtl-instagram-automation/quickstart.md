# راهنمای اعتبارسنجی و راه‌اندازی سریع (Phase 1: Quickstart Validation Guide)
# ویژگی: `001-persian-rtl-instagram-automation`

این سند فرآیند تست، تایید کارکرد سرتاسری (End-to-End) و راستی‌آزمایی ویژگی‌های بومی‌سازی فارسی، چیدمان RTL و اتوماسیون اینستاگرام را گام‌به‌گام توضیح می‌دهد.

---

## ۱. پیش‌نیازهای محیط اجرا (Prerequisites)

1. **موتور جاوا اسکریپت:** Node.js نسخه 20 به بالا
2. **پایگاه داده:** PostgreSQL نسخه 15 به بالا
3. **پایگاه کش و صف:** Redis نسخه 7 به بالا
4. **متغیرهای محیطی ضروری (`.env`):**
   ```env
   DATABASE_URL="postgresql://user:password@localhost:5432/openreply"
   REDIS_URL="redis://localhost:6379"
   NEXTAUTH_SECRET="your-32-char-random-secret"
   NEXTAUTH_URL="http://localhost:3000"
   ENCRYPTION_KEY="64-character-hex-encryption-key"
   INSTAGRAM_APP_ID="your-meta-app-id"
   INSTAGRAM_APP_SECRET="your-meta-app-secret"
   WEBHOOK_VERIFY_TOKEN="your-custom-webhook-verify-token"
   ```

---

## ۲. سناریوهای اعتبارسنجی گام‌به‌گام (Verification Scenarios)

### سناریو ۱: راستی‌آزمایی بومی‌سازی، زبان فارسی و چیدمان RTL
* **هدف:** اطمینان از اعمال کامل `dir="rtl"`، لود صحیح فونت وزیرمتن و عدم شکست المان‌ها.
* **مراحل اجرا:**
  1. اجرای وب‌اپلیکیشن: `npm run dev`
  2. ورود به صفحه اصلی در مرورگر: `http://localhost:3000`
  3. کلیک بر روی انتخاب‌گر زبان و تغییر به **«فارسی»**.
* **نتایج مورد انتظار (Expected Outcome):**
  * تگ `<html>` دارای صفت‌های `lang="fa"` و `dir="rtl"` شود.
  * منوی سایدبار به لبه راست مرورگر منتقل شود (`start-0`).
  * فونت متن‌ها به صورت روان و با تایپوگرافی وزیرمتن رندر گردد.
  * آمارها و ارقام کارت‌ها به صورت اعداد فارسی (`۰۱۲۳۴۵۶۷۸۹`) نمایش داده شوند.
  * در نمای موبایل (عرض زیر ۶۴۰ پیکسل)، دراور سایدبار از سمت راست با انیمیشن ملایم باز شود و اسکرول افقی در هیچ صفحه‌ای رخ ندهد.

### سناریو ۲: راستی‌آزمایی تاییدیه وب‌هوک (Webhook Handshake)
* **هدف:** اطمینان از عملکرد صحیح هندشیک متا برای فعال‌سازی وبهوک.
* **دستور تست (curl):**
  ```bash
  curl -X GET "http://localhost:3000/api/webhook?hub.mode=subscribe&hub.verify_token=your-custom-webhook-verify-token&hub.challenge=1234567890"
  ```
* **نتیجه مورد انتظار:**
  * کد وضعیت HTTP 200 و مقدار خالص `1234567890` در بدنه بازگردانده شود.

### سناریو ۳: راستی‌آزمایی پذیرش سریع وب‌هوک و صف‌بندی غیرمسدودکننده
* **هدف:** اطمینان از پاسخ زیر ۳۰۰ میلی‌ثانیه و انتقال پیلود به ردیس.
* **مراحل تست:**
  1. اجرای ورکر در ترمینال دوم: `npm run worker`
  2. شبیه‌سازی ارسال رویداد کامنت اینستاگرام با اسکریپت تستی یا cURL با هدر امضا `x-hub-signature-256`.
* **نتیجه مورد انتظار:**
  * اندپوینت `/api/webhook` در کمتر از ۳۰۰ میلی‌ثانیه پاسخ `{ "success": true }` دهد.
  * در لاگ ترمینال ورکر پیام `[BullMQ] Job 'process-comment' received` نمایش یابد.
  * رکورد جاب بدون خطای تایپ در صف قرار گیرد.

### سناریو ۴: راستی‌آزمایی تمدید خودکار توکن‌های بلندمدت
* **هدف:** تضمین سلامت توکن‌ها بدون نیاز به دخالت کاربر.
* **مراحل تست:**
  1. تنظیم تاریخ انقضای یک اکانت تستی در دیتابیس به ۵ روز آینده.
  2. اجرای تسک ورکر برای بررسی توکن‌ها.
* **نتیجه مورد انتظار:**
  * ورکر اکانت را شناسایی کند، متد نوسازی متا را فراخوانی کرده و فیلد `tokenExpiresAt` در دیتابیس به ۶۰ روز بعد آپدیت شود.
  * وضعیت سلامت توکن روی `HEALTHY` باقی بماند.

## ۳. دستورات تایید سلامت سیستم (Health Check Commands)

```bash
# اعتبارسنجی کامل تایپ‌های تایپ‌اسکریپت
npm run typecheck

# اجرای تست‌های خودکار واحد و یکپارچه‌سازی
npm run test

# بررسی وضعیت صف و ورکر
npm run worker
```
