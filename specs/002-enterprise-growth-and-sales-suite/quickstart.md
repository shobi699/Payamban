# راهنمای اعتبارسنجی و اجرای سریع (Quickstart Validation Guide)
# ویژگی: `002-enterprise-growth-and-sales-suite`
# پلتفرم: دی‌رکت پرو (OpenReply Engine)

---

## ۱. پیش‌نیازها و راه‌اندازی محیط تست (Prerequisites)

1. سرور PostgreSQL و Redis فعال (از طریق `docker-compose up -d`).
2. وابستگی‌های پروژه نصب شده باشند (`npm install`).
3. تنظیم متغیرهای محیطی اصلی در `.env` (مقادیر `DATABASE_URL`, `REDIS_URL`, `NEXTAUTH_SECRET`, `ENCRYPTION_KEY`).

---

## ۲. سناریوهای اعتبارسنجی سریع (Runnable Validation Scenarios)

### سناریوی ۱: اعتبارسنجی انتشار مستقیم پاسخ کامنت
* **دستور تست:**
  ```bash
  npm run test -- __tests__/comments-reply.test.ts
  ```
* **نتیجه مورد انتظار:**
  تست با ارسال شناسه کامنت و توکن شبیه‌سازی‌شده، تابع `sendCommentReply` را فراخوانی کرده و موفقیت بازگشت کد ۲۰۰ و به‌روزرسانی وضعیت در دیتابیس به `REPLIED` را تایید می‌کند.

### سناریوی ۲: تست ماشین وضعیت چندمرحله‌ای فرم‌های دایرکت
* **دستور تست:**
  ```bash
  npm run test -- __tests__/dm-state-machine.test.ts
  ```
* **مراحل:**
  1. شبیه‌سازی پیام اول: "ثبت‌نام" ➔ سیستم کلید سشن را در ردیس ساخته و سوال "نام شما؟" را بازمی‌گرداند.
  2. شبیه‌سازی پیام دوم: "علی رضایی" ➔ سیستم نام را ذخیره کرده و سوال "شماره تماس؟" را می‌پرسد.
  3. شبیه‌سازی پیام سوم نامعتبر: "12345" ➔ سیستم خطای اعتبارسنجی داده و مجدداً شماره معتبر می‌خواهد.
  4. شبیه‌سازی پیام چهارم معتبر: "09123456789" ➔ سیستم فرم را پایان داده، رکورد `DmFormSubmission` را ثبت و پیام تایید ارسال می‌کند.

### سناریوی ۳: تست چرخه پرداخت زرین‌پال و تمدید اشتراک
* **دستور تست:**
  ```bash
  npm run test -- __tests__/payment-zarinpal.test.ts
  ```
* **نتیجه مورد انتظار:**
  شبیه‌سازی دریافت Authority از زرین‌پال، بازگشت موفق از Callback بانکی با کد ۱۰۰ و بررسی افزایش ۳۰ روز به فیلد `expiresAt` در جدول `Subscription`.

### سناریوی ۴: بررسی سلامت تایپ‌ها و عدم وجود خطای کامپایل
* **دستور تست:**
  ```bash
  npm run typecheck
  ```
* **نتیجه مورد انتظار:**
  خروجی کد ۰ بدون حتی یک خطای تایپ‌اسکریپت در تمامی صفحات و ماژول‌ها.
